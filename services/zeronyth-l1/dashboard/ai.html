What the interface will connect to

The browser uses these lab routes for status, explicit evaluation and training starts, and consent-based worker participation.

  • GET /ai-lab/statusReturns {mode, modelRegistry, evaluation, training, workers}
  • POST /ai-lab/evaluation/start · POST /ai-lab/training/startStarts a fixed public experiment with {confirm:true}
  • POST /ai-lab/worker/joinAccepts {role,consent:true} after explicit role consent
  • GET /ai-lab/worker/nextBearer-authenticated; returns the next permitted task
  • POST /ai-lab/worker/result · POST /ai-lab/worker/gradient · POST /ai-lab/worker/leaveBearer-authenticated worker requests
  • POST /ai-lab/models/adoptExplicitly adopts only a fully evaluated improved candidate

04 / READ BEFORE PARTICIPATING

A fenced experiment, by design

  • No value.No payments, rewards, tokens, or wallet actions.
  • Not Sybil resistant.Worker identity and participation do not establish uniqueness.
  • Not a trained LLM.The training example is a toy logistic classifier, entirely separate from public ONNX inference.
  • No production or chain changes.No Besu validator training, candidate approval, chain writes, or deployment changes.
  • Consent first.Remote evaluation and training require separate explicit opt-in and a user click.
Evaluation and training contract notes

POST /ai-lab/evaluation/start with {confirm:true} starts the fixed public evaluation set.

POST /ai-lab/training/start with {confirm:true} starts an isolated classifier training round.

POST /ai-lab/models/adopt accepts {kind,candidateId,confirm:true} and only accepts a candidate that beat the previous score.

POST /ai-lab/worker/join accepts {role,consent:true}. Bearer authentication protects the worker task, result, gradient, and leave routes.
