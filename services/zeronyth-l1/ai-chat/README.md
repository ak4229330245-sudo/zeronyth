# ZERONYTH chat AI (v1, testnet)

What is real: a small open model (Qwen3-4B-Instruct-2507 Q4_K_M, Apache-2.0) served by Ollama on the box CPU
(`deploy/run-ollama.sh`, `deploy/Modelfile.znyt`, pm2 `zeronyth-ai-ollama`, nice 19, about 3.4 GB RSS, about 7 tok/s),
plus `chat-server.mjs` (pm2 `zeronyth-ai-chat`, 127.0.0.1:9803) with BM25 retrieval over the Japanese FAQ in `kb/`.

Path: browser `chat.html` -> gateway `/api/ai/{status,chat,feedback}` (per-IP limits: chat 6/min, feedback 30/min,
status 5/s; body limit 24 KB for chat and 4 KB otherwise; NDJSON streamed) -> VPS tunnel 127.0.0.1:8803 -> box 9803 -> Ollama 11434.

Privacy: only opt-in conversations and 👍/👎 go to `data/` (0700/0600; no IPs; keys, emails, phones and mnemonics
redacted; messages that look like secrets are refused and not stored). Opt-in is off by default in the UI.

## Learning (v2)

1. **Learned memory (real, automatic).** pm2 `zeronyth-ai-learner` runs `learner.mjs run` every 30 min (nice 19, ionice idle).
   - 👍 opted-in answers (server-generated, redacted) pass filters in `lib/safety.mjs`: secrets, prompt injection, abuse,
     financial advice, asking for keys, sending funds, foreign links, canonical fact contradictions (chain ID 9127, AI 5 / VPS 10
     ZNYT, 10 days, 20% burn, 4 validators, 1e8 supply, ZNYT has no value, plans are escrowed), minimum quality.
   - Dedupe by bigram Jaccard / e5 cosine. Max 20 new items per run. A later 👎 removes the item; items that keep getting 👎 are dropped.
   - 👎 answers -> `needs-faq` queue; questions answered without kb sources or with "わかりません" -> `unanswered` queue (clustered,
     shown when asked ≥2 times). Operator: `node learner.mjs queue | approve <key> "<answer>" | dismiss <key> | forget <id>`.
   - **Eval gate**: the fixed Japanese set `eval/eval-set.json` (retrieval level) must not regress and each new item must be
     retrievable by its own question; otherwise the snapshot is saved but not promoted.
   - Snapshots: `data/learned/versions/vNNNN.json`, pointer `data/learned/current.json`. **Rollback**: `node learner.mjs rollback [vNNNN]`
     (items added after the target are blocked from coming back). chat-server hot-reloads the pointer (10 s), no restart.
   - Retrieval: BM25 + cosine over `znyt-embed` (multilingual-e5-small Q8_0, 384-dim, ~130 MB, converted with
     `deploy/convert-e5-gguf.py`). Falls back to BM25-only if Ollama embeddings fail. kb wins over learned memory on conflicts.
2. **LoRA fine-tune (real pipeline, small).** pm2 `zeronyth-ai-finetune` runs `finetune/nightly.sh` at 03:30 JST:
   prepare (seed-sft + learned memory, eval questions excluded) -> `train_lora.py` (Qwen2.5-0.5B-Instruct, bf16 LoRA r=8 q/k/v/o,
   2 threads, nice 19, `timeout 45m`, watchdog: abort if MemAvailable < 1200 MB or RSS > 3200 MB) -> merge -> GGUF Q8_0 ->
   Ollama candidate -> `finetune/ab.mjs` (LLM eval, same context, temperature 0) vs the current model -> promote only if strictly
   better and all safety cases pass (`data/model/current.json`, hot-reloaded). Undo: `node learner.mjs model-rollback`.
   Skips if MemAvailable < 3500 MB, chat busy, or data unchanged. On this CPU-only box a 0.5B candidate is not expected to beat
   the 4B chat model, so it normally stays on the 4B model; the same scripts are meant for participant GPU nodes later.
3. **Eval**: `node eval.mjs [--llm --model X] [--version current|none|vNNNN] [--extra eval/demo-cases.json]`.
   Demo data: `ZERONYTH_AI_DATA=/tmp/x node eval/seed-demo.mjs` (synthetic, marked `synthetic:true`).
4. **Public status**: `/api/ai/status` -> `learning` (counts, versions, times, eval score; no conversation text) and `/learning.html`.

Honest limits: anyone can opt in and 👍 their own conversation, but answers are generated by the server (users cannot type
the answer), filters + fact gate + caps apply, and kb has priority. `build-dataset.mjs` still exports offline datasets.
