# ZERONYTH AI v1.8.28 — iPhone AIラボとテストZNYT精算

## 追加されたもの

- **iPhoneブラウザー用 AI Chat**: UIからAIに質問して、実際のlocalhost Ollamaモデルが回答した場合のみ表示。架空の回答は出さない。
- **テストユーザーモード**: 明示的に前払い予約した `ZNYT_LAB_NOT_REAL_TOKEN` だけを使用する。モデル回答の署名が検証されてから、双方の承認で精算できる。
- **ノード提供者モード**: 既存のボンド＋端末認証＋有効な稼働報告を満たした**試験提供者**だけ、1エポック20回のAI無料枠を利用。実際のモデル出力を受けたときだけ利用枠を消費する。
- **提供者AI worker**: ML-DSA-65署名で拘束されたモデル・顧客・レンタルID・nonce・期限・最大トークン数をチェックし、許可済みlocalhost Ollamaに生成を依頼。返答本文のSHA-256ドメインハッシュと署名付き結果を作成する。
- **ローカルAPI**: 管理者トークンでのみAI質問とテスト精算にアクセスできる。常に `127.0.0.1` にバインド。

## ZNYTは**テスト専用**

今回のテスト環境では、起動ごとに作る独立した研究用ウォレットへ**架空の試験残高**を割当てる。**ZNYT-LAB**はテストネット契約上の実トークンではなく、ZERONYTHの isolated ML-DSA 経済モデルのメモリ残高。既存のBesu/EVM試験用ZNYTはこれと別物。

| 項目 | v1.8.28 |
| --- | --- |
| ユーザーの初期試験残高 | 1,000 ZNYT-LAB をメモリに仮配分 |
| AI利用の予約例 | 2スロット × 20 = 40 ZNYT-LAB 仮エスクロー |
| 有効なAI出力がない場合 | 精算不可、提供者への振込不可 |
| 利用1スロットの相互承認 | 20 ZNYT-LAB を試験精算、提供者へ19、試験手数料1、未利用20は顧客へ返却 |
| ノード提供者のAI特典 | 適格な試験バリデータ登録者に20リクエスト／10ブロックの無料枠 |
| 本番ZNYT・実テストネット送金 | **未対応。RPCとトークン定義、独立決済確認が今後必要** |
| 現実の生成AI | localhostの許可済みOllamaがインストール・稼働中なら実回答可能 |
| 実GPU使用と不正防止 | **未検証**。GPUを保有していないPCでもCPUでOllamaを動かせるため表示で偽らない |

## 自分のPCなしで試す

既存のLinux VPSまたは有志のLinuxホストにNode.js 24+ と**自分で使用を許可したOllamaモデル**を準備する（モデルのライセンス、消費メモリ、速度、プロンプトの保存に注意）。このキットはOllama本体やモデルを勝手にダウンロードしない。

1. Ollamaがオペレーター管理下の `http://127.0.0.1:11434` で稼働していることを確認する。
2. オペレーターが事前に許可しインストールしたモデル名を確認。例 `qwen2.5:0.5b` は**例であり、存在は保証しない**。
3. 32文字以上の秘密トークンを環境変数 `ZERONYTH_AI_ADMIN_TOKEN` に設定する。設定値をURL、画面、ZIPへ記録しない。
4. プロジェクトルートで起動:

   ```bash
   node pq-native/ai-local-demo.mjs qwen2.5:0.5b 18920
   ```

5. ブラウザーで `http://127.0.0.1:18920/` を開き、管理者トークンで接続する。「一般利用」「ノード提供者」を切り替えて質問する。一般利用の精算は**別の『テスト精算を承認』ボタン**を押したときだけ発生する。
6. iPhoneから閲覧する場合も、事前に管理者が適切に構築した認証付きVPN／SSHトンネル、または安全なTLS逆プロキシを使用する。この版で公開インターネット配信を設定する機能はない。

### 実装・テストの扱い

- デモは起動時に使い捨てML-DSA鍵、**架空の**validator署名・GPU容量証明、1000 ZNYT-LABの試験残高を作る。再起動するとセッションと残高が初期化される。実際に第三者のバリデータが参加・署名した証拠ではない。
- `ai-inference-worker.mjs` は本物のローカルOllama APIを呼べる。テスト時はモックHTTPレスポンスを使用したので、**この開発環境でOllamaの実推論・GPU計算が動いたわけではない**。
- ユーザー入力のプロンプトはローカルサーバーで署名しローカルOllamaへ送る。永続ログや会話履歴を作らない。AIモデル自身のログ設定は別途確認する必要がある。
- **外部GPU提供者へのプロンプト送信は実装していない**。遠隔ノードに質問を送るには、その送信先・データの保存方針・提供者への開示について利用者の明示的承認と暗号化通信、信頼検証が必要。
- 契約・本番L1・本物のテストネットZNYT・実トークン決済には**一切接続していない**。

## 次の本物のテストネット段階

1. テストネット上で使用するZNYTの**チェーンID・通貨仕様・実際のRPC・デプロイ情報**を固定し、既存のBesu ZNYTとML-DSA研究台帳の違いを解決する。
2. ブラウザーウォレットが支払い意図・上限・期限を署名する。**管理サーバーは本物の顧客秘密鍵を保管しない**。
3. 先払いエスクローと、実行証明を受け取った後の利用者の明示的承認・払い戻し・二重精算防止を、実際のテストネットトランザクションとして実装する。
4. GPU提供者とAIユーザーとの間で、外部質問文の送信先を明示し、認証・TLS・個人情報の扱いに同意してから遠隔実行を接続する。
5. GPUボンド・実在性、複数独立バリデータ署名と稼働証明を本物のP2Pネットワークへ移行する。

この版は**ローカルテストネット経済の実演**であり、実際のブロックチェーン上のトークン交換や一般公開AIサービスではない。
