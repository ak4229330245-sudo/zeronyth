# ZERONYTH v1.8.27 — 自動ノード参加の安全なローカル試作

## 誰が何をするか

- **ネットワーク管理者（直也）:** 自分のPCは不要。既存のLinux VPS上にコーディネーターを設置し、iPhoneのブラウザーから**管理者限定**のノード一覧を見る。iPhoneにサーバー鍵は持たせない。
- **資源提供者（有志）:** 自分のLinux PC/VPSで**本人の明示的同意**により `provider-join-agent.mjs` を起動し、CPU/RAM/GPUの概況と提供割合を署名して送信する。CPU負荷を30秒ごとに通知する。秘密鍵は提供者のホスト外へ出さない。
- **ブロックチェーン:** `qspq_` ML-DSA-65署名、チェーンID、nonce、時刻・リプレイ防止を**この参加受付について**実装した。既存のコンセンサスやライブZNYTに接続したわけではない。

## 動作済み機能と非対応範囲

| 機能 | v1.8.27 | 備考 |
| --- | --- | --- |
| 登録数 | 固定の総数上限なし | CPU/RAM、運用容量、APIレート、イベント記録64 MiB制限は別途存在する |
| ノードの自己申告署名 | 実装 | ML-DSA-65、chainId、連続nonce、±120秒の時刻確認 |
| CPU/RAM自動検出 | 実装 | 利用可能CPU並列度と総RAMの申告、硬いリソース検証ではない |
| GPU検出 | NVIDIA `nvidia-smi` のみ試行 | 他GPUは未検出扱い。GPU利用の権限・存在を検証しない |
| 配分比率 | 初期値L1 20%/AI 20%/VPS・GPU 60% | 合計100%検証、**実行隔離やCPU割当は未実装** |
| ハートビート | 署名付きで実装 | 90秒以内ならオンライン表示。実際の業務実行の証明ではない |
| ノードの管理画面 | スマホ対応 | bearer tokenで認証した時のみノード一覧を取得 |
| ZNYTガバナンス報酬 | **未付与** | 既存v1.8.24の「ZNYT-LAB」経済モデルはシミュレーション |
| 提供者のAI利用権 | **未付与** | ボンドと仕事の独立検証・有効な権限付与が今後必要 |
| L1の新規バリデータ追加 | **未実装** | 登録だけでは既存の合意形成に参加しない |
| 実際のGPU・VPS・生成AIレンタル | **自動連結なし** | v1.8.26に手動・許可制Docker/Ollamaバックエンド試作あり。実GPU未検証 |

## Linux VPSで起動する手順（管理者）

1. Node.js 24+ を用意する。`node --version` で確認する。
2. 誰にも見せない**32文字以上のランダムな管理者トークン**を環境変数 `ZERONYTH_JOIN_ADMIN_TOKEN` に設定する。URL、ソース、公開画面や配布ZIPに保存しない。
3. カレントディレクトリをスターターキットのルートにして起動する（記録ファイルの親ディレクトリは管理者所有、他者から書込み不可にしておく）。

   ```bash
   node pq-native/node-join-coordinator-cli.mjs 19127 /absolute/private/node-events.jsonl 18890
   ```

4. API・画面は `http://127.0.0.1:18890/` にしかバインドされない。ブラウザーで開くと、**管理者トークンを手入力するまでは一覧非表示**。
5. iPhoneから見るには、管理者自身が設定した**認証付きVPN、SSHトンネル、またはTLS逆プロキシ**を使う。転送先の公開アクセスにはHTTPS必須。認証・rate limit・リバースプロキシのアクセス制御を導入するまでインターネットに公開しない。HTTPのまま `0.0.0.0` で公開してはいけない。

## 提供者が自分のPC / Linux VPSを登録

1. 管理者が承認した配布元のキットを確認する。提供者が自分のホストで鍵を作る。

   ```bash
   node pq-native/create-provider-key.mjs /absolute/private/provider-key.pem
   ```

   既存ファイルへの上書きは禁止。キーは `0600` で作成し、秘密鍵は共有しない。
2. 提供者自身が `provider-config.json` を用意する。例:

   ```json
   {
     "consent": true,
     "chainId": "19127",
     "privateKeyFile": "/absolute/private/provider-key.pem",
     "coordinatorUrl": "https://nodes.example.com/",
     "deviceClass": "server",
     "l1Percent": 20,
     "aiPercent": 20,
     "rentalPercent": 60,
     "heartbeatSeconds": 30
   }
   ```

   `nodes.example.com` は**説明用の架空ドメイン**。管理者がTLSとアクセス制御を正しく設定した実際のホスト名に変更する。コーディネーターと同一ホストで試すときのみ `http://127.0.0.1:18890/` を使える。
3. 本人が同意した場合だけ起動する。

   ```bash
   node pq-native/provider-join-agent.mjs /absolute/provider-config.json
   ```

   一度だけ登録したい場合は末尾に `--once`。停止は `Ctrl+C`。削除や退出のAPIはまだないため、登録は管理者管理の試作扱い。

## 署名する情報と権限

- 公開ノードID、端末種別、CPUコア数、RAM MiB、NVIDIA GPUの個数と短い製品名、L1/AI/貸出の配分、明示的同意フラグ、発行時刻、nonce、公開鍵。
- ハートビートは公開ノードIDに紐づく署名でCPU負荷（%）を報告する。GPU稼働率は未検出のため `unknown`。
- このツールは**クラウド上で勝手に命令を実行しない**。ファイルを読んだりDockerを動かしたりGPUを貸す機能も参加エージェントには付与していない。
- コーディネーターには `ZNYT` を残高加算するAPIはない。管理画面でも `ZNYT未認証 / AI特典未認証` と表示。

## 次の開発で実際のP2Pエコシステムに必要なもの

1. ノード認証：偽のCPU/GPU申告やSybil参加を防ぐため、検証者の署名、ボンド、GPUタスク実行の成果検証。
2. スケジューラー：ノードごとのCPU/RAM/GPU強制制限、許可制のワークロード、途中離脱と再試行、隔離された租借コンテナ。
3. ZNYT経済との正式連結：証明された仕事に基づく費用と報酬、上限・不正対策、燃焼・ガバナンスと供給量監査。現状はZNYT-LABのみ。
4. 提供者の生成AI利用：実モデル・実GPUの処理量メータリングと認可、費用上限を設けた特典発行。
5. 本番ネットワーク：ブロックチェーンの実際のバリデータ加入手順、WANネットワークでの合意、管理UI保護、運用監視、バックアップ、TLS・鍵ローテーション、ジャーナル保持・圧縮、多台数同時アクセスのロード検証。

現時点は**動かせるローカル参加受付試作**であり、公開ブロックチェーン、収益サービス、完成版クラウドレンタルプラットフォームではない。
